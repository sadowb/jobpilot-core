# JobPilot dashboard

Run `pnpm --filter @jobpilot/frontend dev` from the repository root. Vite proxies `/api` to the local backend at `http://127.0.0.1:4100`.

Check with `pnpm --filter @jobpilot/frontend typecheck` and `pnpm --filter @jobpilot/frontend build`. The build is written to `frontend/dist`; production must serve `index.html` for dashboard routes and keep `/api` on the same origin. Assets and fonts are local; no inline scripts or remote resources are used.

Screens: Today, Pipeline (50-job pages and a board view of the current page), Job detail, Needs you, Automation, About me, CV tracks, Accounts, and Settings. Theme follows the system until a manual preference is saved. Approval dialogs list the jobs and require a scope; approval state always comes from the server.

API assumptions:

- `src/api/types.ts` is generated by `openapi-typescript`. Run `pnpm --filter @jobpilot/frontend gen:api` to export the backend OpenAPI schema with `backend/.venv/bin/python` and regenerate it. The intermediate `openapi.json` is ignored; never hand-edit generated types. `src/api/models.ts` names generated contracts. `src/api/api.ts` lists named operations; `src/api/http.ts` handles sessions, fetch and errors. Read [the beginner walkthrough](../docs/frontend-api-walkthrough.md) for every method and the request flow.
- Job lists are arrays without a total count. Next is available when a full 50-job page is returned; a final empty page is possible.
- Form `filled` and `verified` are booleans. The dashboard shows an approval action when no fields are missing and verification is true. The server performs final eligibility and draft-hash checks.
- Missing answers are saved together; the answers endpoint resumes the job. Jobs without missing answers use `/resume`. No stored password/code fields are collected.
- `/events` emits JSON arrays with three entries (stats, automation status and event watermark). Valid messages invalidate queries. EventSource reconnects automatically; queries also refresh every 30 seconds.
- Profile values are displayed as text (including boolean/numeric values); edits and answer text are strings; CV track and board references use their IDs. CV version hashes may be null before the first version. Board limits are integers from 0 to 500. Approval scopes require at least three characters. Account creation accepts an HTTP(S) origin and a required scope.
- Automation shows the separate worker’s connectivity, idle reason and daily cost/token usage, including reserved calls. Daily limits reset at midnight UTC. Start/Stop controls the automation flag.
- Settings uses GET/PUT `/api/v1/settings`. Save requires stopped automation and drained active leases; server validation messages are displayed verbatim from `{error: ...}`.
- Job details distinguish uncertain submissions and manual applications using the returned blocked reason. Submission confirmation uses `/user-confirmed`; confirmed outcomes use the user-only `/status` route. The server validates transitions.
- `/api/v1/session` returns a nonempty CSRF token. Each request retries once after a 401; other failures surface the backend error. Mutation retries are disabled to avoid repeating submissions.

Styling uses Tailwind CSS v4 utility classes, with design tokens in the `@theme` block in `src/styles/tailwind.css`. Shared controls live in `src/components/ui/` and shared style strings in `src/components/ui/styles.ts`; keep component styling in utilities.

## Source map

- `main.tsx`: mounts React; `app/`: application providers, layout/routing, theme and server events.
- `pages/`: screen composition, with feature components imported from `features/`.
- `features/`: profile, approvals, automation, CV previews, needs-you inbox and tracker code.
- `components/ui/`: shared buttons, cards, dialogs, chips, tables, loading/error states and toasts. Internal UI imports are direct; the `index.ts` entry point is for consumers.
- `hooks/`: reusable hooks such as `useAction`, `useMedia`, `useInView` and `useUrlParams`.
- `utils/`: ordinary functions for formatting, files and CSS class merging. `humanize.ts` maps backend data to display text.
- `api/`: HTTP client and generated contracts; `styles/`: Tailwind tokens and global CSS.

Run `pnpm --filter @jobpilot/frontend lint`, `typecheck`, `format:check` and `build` before finishing a change. The linter checks React hook rules and dependencies; Prettier keeps JSX readable. Shared buttons default to `type="button"`; use `type="submit"` explicitly inside forms. The in-memory QA server is `pnpm --filter @jobpilot/frontend exec vite --config vite.mock.config.ts`; it never calls the real backend.
